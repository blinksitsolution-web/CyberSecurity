# Data integrity

## Goal

Design integrity rules and a careful way to handle sensitive fields. Tuesday's assignment is this checklist.

## What was built

`integrity-checklist.csv` lists rules you can apply to a lab database. Status starts at `not-applied`. Sensitive data here means anything covered by Act 843 once it is about a real person: names, contact details, account identifiers.

## How to reproduce

1. Mark a rule `applied` only if the demo or your class database enforces it.
2. Mark `planned` if you know how you would enforce it and have written that down.
3. For any real personal data, record where it is allowed to live. The sample database in this repo uses fake secrets only.
