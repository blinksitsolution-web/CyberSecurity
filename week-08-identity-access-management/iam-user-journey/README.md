# IAM user journey

## Goal

Map identification, authentication, and one delegated-access flow. Monday looks at MFA choices. Friday looks at OAuth 2.0 and OpenID Connect. This is a diagram and a narrative, not a login you must build.

## What was built

`user-journey.md` separates "who is this?" from "prove it" and from "what may they do?". The OAuth section names the roles in ordinary language.

## How to reproduce

1. Fill the journey for a SOC analyst opening the Wazuh dashboard.
2. Fill the second journey for a fictional app that asks to "read your calendar". Mark it as a paper exercise.
3. Stop when you can say which token or password should never appear in a log.
